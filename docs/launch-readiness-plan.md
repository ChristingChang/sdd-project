## 1. 目標與範圍

開放給社團外的陌生人使用前，補齊四件事：

| # | 項目 | 為什麼要做 | 優先 |
|---|---|---|---|
| A | 隱私權說明頁 | 收集手機號碼、LINE ID、LINE 暱稱與頭像，個資法第 8 條要求蒐集時告知 | P0 |
| B | 使用須知（免責聲明） | 講清楚平台只負責媒合、車資限分攤油資、乘車安全由雙方負責 | P0 |
| C | 聯絡管道（檢舉、刪除帳號） | 被放鳥、被騷擾、想刪資料時要找得到人；目前完全沒有 | P0 |
| D | 沒加官方帳號好友的提醒 | user-stories.md 列為最大風險：沒加好友，通知全部收不到，故事就斷了 | P0（提醒）／P1（偵測） |

**P0 = 開放陌生人前必須完成；P1 = 開放後第一批改善。**

不在範圍內：站內檢舉系統、封鎖使用者、評價機制、司機身分驗證、駕照或保險檢查。

## 3. 各項做法

### A. 隱私權說明頁 `/privacy`

**內容**（對應個資法第 8 條應告知事項）：

1. 蒐集者：浪乘（個人經營，列出負責人稱呼與聯絡方式）
2. 蒐集目的：共乘媒合、通知推播、聯繫司機與乘客
3. 蒐集的資料：
   - 從 LINE 取得：LINE 使用者識別碼、顯示名稱、頭像網址
   - 你自己填的：聯絡方式（LINE ID 或手機號碼）
   - 使用過程產生的：發布的行程、申請紀錄（上車點、板型）、登入紀錄
4. 誰看得到：
   - 聯絡方式**只給被接受的對方**看（司機看到已接受的乘客，乘客看到接受自己的司機）；公開頁面和分享發文都不會出現
   - 顯示名稱會出現在行程頁與申請列表
   - 不提供給第三方，不做廣告用途
5. 存放地點與期間：存放的主機／地區（部署後填）；帳號存續期間保存，申請刪除後於 N 天內刪除（見待決事項）
6. 你的權利（個資法第 3 條）：查詢、閱覽、要求複本、更正、停止使用、刪除。行使方式：寄信到聯絡信箱（C 項）
7. 不提供的影響：不填聯絡方式就不能發行程或申請
8. Cookie：只用一個登入用的 cookie，沒有追蹤或分析工具
9. 更新紀錄：最後更新日期

**畫面上的入口**
- 首頁底部、「我的」頁底部各一個連結
- 填聯絡方式的表單下方加一行：「送出即表示同意 [隱私權說明] 與 [使用須知]」（這是取得同意的關鍵位置）
- LINE 登入按鈕下方同樣一行小字

### B. 使用須知 `/terms`

用白話寫，不要寫成法律條文，重點：

1. **浪乘只負責媒合**：不是運輸業者，不提供車輛、不安排司機，也不保證行程一定成行
2. **車資只能分攤油資與過路費**：不得以營利為目的載客（避免變成非法營業載客）；建議金額參考現有社團行情
3. **安全由雙方自行負責**：上車前自行確認對方身分、車況；建議第一次搭乘先告知親友行程
4. **浪板與財物**：運送中的損壞由雙方自行協議
5. **禁止行為**：騷擾、冒用他人身分、留假的聯絡方式、把對方聯絡方式用在共乘以外
6. **違規處理**：營運者可以刪除行程或停用帳號
7. **放鳥**：說明目前沒有評價機制，遇到請來信告知，累犯會被停用

### C. 聯絡管道

- **P0（最小可行）**：一個專用 email（建議另開，不要用個人主信箱），出現在：
  - `/privacy`、`/terms` 頁面
  - 首頁與「我的」頁底部：「遇到問題、被放鳥、想刪除帳號？寫信給 xxx」
  - email 用 `.env` 設定（例如 `SUPPORT_EMAIL`），經 `/api/config` 帶到前端，不寫死在程式碼
- **來信的處理 SOP**（寫在 `docs/` 給自己看）：
  - 刪除帳號：確認是本人（請對方用登入的 LINE 顯示名稱＋聯絡方式核對），然後執行刪除腳本（見下）
  - 騷擾檢舉：停用對方帳號、必要時取消對方行程
- **刪除帳號的做法**（需要決定，見待決事項 Q3）：
  - P0：寫一支管理腳本 `npm run delete-user -- <userId>`，手動處理來信
  - P1：「我的」頁加「刪除帳號」按鈕，自助刪除
  - 刪除時的行為建議：清空 `contact`、`picture_url`，`display_name` 改成「已刪除的使用者」，`line_user_id` 改成無法對應的值，刪除所有 session；未出發的行程自動取消並通知乘客；待確認／已接受的申請改為退出並通知司機。已出發的歷史行程保留（匿名化），才不會讓「每週成行趟數」統計壞掉

### D. 沒加官方帳號好友就收不到通知

分兩階段：

**D1（P0）：畫面提醒，不偵測**
- 「我的」頁最上方、發布行程成功後、送出申請成功後，各顯示一則提醒：「記得加浪乘官方帳號好友，才收得到申請和接受通知」＋「加好友」按鈕
- 按鈕連到 `https://line.me/R/ti/p/@<官方帳號 ID>`，官方帳號 ID 放 `.env`（例如 `LINE_OA_BASIC_ID`），經 `/api/config` 帶出
- 宣傳素材的「不要說的話」維持不變

**D2（P1）：偵測好友狀態，只對沒加的人顯示**
- LINE 登入完成後，用登入拿到的 access token 呼叫 LINE 的「好友狀態」API（`GET https://api.line.me/friendship/v1/status`），把結果存到 `users` 新欄位（例如 `is_friend`）。前提：LINE Login channel 要在 LINE Developers 後台連結到官方帳號（實作前先確認 `docs/line-setup.md` 的設定）
- 每次登入都更新一次（使用者可能後來封鎖官方帳號）
- 前端只在 `is_friend = false` 時顯示 D1 的提醒，並把提醒升級成醒目樣式
- 司機的申請列表上，對沒加好友的乘客標示「可能收不到通知，建議主動聯絡」（選做）
- 再進一步（P2，不在本次範圍）：接 Messaging API webhook 的 follow／unfollow 事件即時更新。需要公開 HTTPS 網址、驗證簽章、新增 channel secret，等部署後再做

## 6. 風險與注意

- **紅線不變**：聯絡方式不能出現在公開 API（`PR-CONTACT-02`）；新頁面不能顯示任何使用者資料。
- **email 不是秘密**但仍放 `.env`，方便正式／測試環境用不同信箱。
- **好友狀態 API 需要 Login channel 與官方帳號連結**，沒連結時 API 會回錯誤，程式要退回 D1 的「一律提醒」，不能讓登入失敗。
- 隱私權說明寫了「N 天內刪除」就要做得到，承諾寫保守一點。
- 開放陌生人後，`data/carpool.db` 就是真的個資，要規劃備份與主機存取權限（部署時另行處理）。

## 7. 模擬律師審閱後追加的決定（2026-11-20）

經一輪 AI 模擬律師審閱（非正式法律意見），追加：

- 經營者平常只顯示 CC，加註「依法行使權利或有法律爭議時，提供真實姓名與聯絡地址」。
- 登入按鈕改為「同意並以 LINE 登入」，記錄同意的條款版本與時間。
- 未滿 18 歲需家長同意（不做年齡驗證）。
- 車資只在使用須知寫「以分攤油資與過路費為原則，明顯違反得下架」；發行程頁不顯示任何車資提醒。
- 免責條款加上「經營者故意或重大過失不在此限」，並加保險提醒。
- 隱私權頁如實揭露 LINE 與主機商受託處理；權利補齊第 3 條五項；查詢、閱覽、複本 15 天內回覆。
- 刪除帳號時一併清除上車點、精確集合點、備註。
- 本人確認改為請對方從 LINE 官方帳號私訊。
- 正式環境沒設定 `SUPPORT_EMAIL` 時伺服器拒絕啟動。
- 「利用地區」必須寫具體國家，選定主機後補上。
